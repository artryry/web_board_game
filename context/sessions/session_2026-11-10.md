# Session 2026-11-10: deployment to Render + Neon + Upstash, with CI

## Summary
Planned and implemented the production deployment, on branch `ci-cd-prepare`. Nothing is committed yet, and the hosted services don't exist yet: the user creates them from the checklist in [current-feature.md](../current-feature.md).
- One Render web service (Docker, free, Frankfurt) runs the API, which also serves the built frontend. Neon for Postgres, Upstash for Redis, R2 for art, all in Frankfurt.
- GitHub Actions checks every push and pull request to `master`; Render deploys only after the checks pass.

## Decisions made

| Topic | Decision |
|---|---|
| Providers | Render free + Neon + Upstash. Railway (~$5/mo), Render Starter (~$7/mo) and a Hetzner VPS (~€4–5/mo) were offered; the user chose $0. Neon and Upstash are their own sign-ups; Cloudflare only lists them as Workers integrations, and Hyperdrive only helps Workers. |
| Shape | One service on one origin: the refresh cookie (`SameSite=Strict`, `Path=/api/auth`) and the same-origin client need it. No CORS, no frontend changes. |
| Postgres | Neon's direct endpoint, not the pooler (asyncpg's prepared statements vs PgBouncer). `Settings` converts `sslmode`/`channel_binding` to asyncpg's `ssl`. |
| Redis | Upstash `rediss://` URL with the password inside; `REDIS_PASSWORD` is now optional. |
| Health | Render polls `/api/health/live` (no service calls): the full `/api/health` would cost Upstash commands and R2 operations every few seconds and keep Neon awake. |
| Migrations | In `scripts/start.sh` before uvicorn, since Render's pre-deploy step is paid-only. |
| Domain | None yet: `onrender.com` and R2's `r2.dev`. |
