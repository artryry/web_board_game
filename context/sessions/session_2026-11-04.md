## Decisions made

| Topic | Decision |
|---|---|
| Deck bounds | 1–4 copies, at most 60 cards, no minimum. The ruleset check comes in M6 and F2. |
| Deck PATCH | `cards` replaces the list. The service diffs the rows (update kept rows, delete dropped ones, add new ones), and a cards-only change bumps `updated_at`. |
| Deck loading | `lazy="raise"` relationships, `selectinload` on read, and a re-load with `populate_existing` after a write. `card_count` and `share_code` are `column_property` subqueries. |
| In-use | `card_in_use` on deleting a card a deck holds, or on an origin change that doesn't fit (neutral always fits). `origin_in_use` lists `cards` and `decks`. The DB backs both up: RESTRICT on the origin FKs, and a deferred FK on `deck_cards.card_id`. |
| User deletion | `deck_cards.card_id` is `NO ACTION DEFERRABLE INITIALLY DEFERRED`, so one `DELETE FROM users` removes a user and all their content (see "Finding"). |
| Cost suggestion | No upper cap, only the floor of 0. A card worth more than 10 is labelled `under` at 10. `mana_cost` stays 0–10. |
| Share codes | One table with `deck_id` / `card_group_id` FKs (CASCADE, UNIQUE, exactly one set). 10 characters from a 31-character no-look-alike alphabet. Created inside a savepoint, with retries. Revoke via DELETE. Lookups upper-case the input. |
| API shapes | `share_code` on deck and group responses. Preview and import responses are discriminated by `kind`. |
| Import | Custom origins are copied once each; system origins are shared. The cards are copied with the same `art_key` into a new group named after the deck or group, with ` (n)` on a name clash. No group for an empty deck. The import bypasses `card_service._apply`. One transaction, with explicit flushes. |
| Pylance | `OwnedMixin` declares `owner_id`, and `get_owned[M: OwnedMixin]` takes loader options. |

## Finding: deleting a user was blocked (fixed)
- **What happened:** the first cleanup, a `DELETE FROM users`, failed with `fk_deck_cards_card_id_cards`. Postgres runs the `users` → `cards` cascade before the `deck_cards` rows go (they cascade through `decks`), so the immediate RESTRICT check fired in between. The failed statement deleted nothing.
- **Correction:** I first guessed that `cards.origin_id` was affected too. It isn't. Cards are a direct cascade from `users`, so they are gone before an origin's check runs. The test proved it.
- **Fix:**
  - `deck_cards.card_id` became `NO ACTION DEFERRABLE INITIALLY DEFERRED`, so the check runs at COMMIT, after every cascade
  - `test_user_deletion.py` was written first and reproduced the error; it brings the deferred check forward with `SET CONSTRAINTS ALL IMMEDIATE`
  - `test_decks.py` checks that the database still refuses to delete a held card
- **Real-commit check:** after a second end-to-end run (16/16), one plain `DELETE FROM users` removed both test users with their decks, deck rows, cards on custom origins and copied origins. 0 rows were left.
- **Forks outlive the author:** an import copies custom origins, so deleting the source origin, deck, group or account leaves the copy as it was, art included (art is never deleted).
