| Forms | React Hook Form `onTouched`; bounds in `auth/bounds.ts`. `username_taken`/`email_taken` go on their field, `validation_error` on each field, and anything else (`invalid_credentials`) in one `role="alert"` message. The server's own messages are shown. |

## Finding: OpenAPI for `GET /api/cards` was wrong (fixed)
- **What happened:** the generated type for `GET /api/cards` needed a required `filters: CardFilters` object, so `api.GET("/api/cards", { params: { query: { limit: 1 } } })` didn't type-check. At runtime the API took flat params (`?limit=2&ungrouped=true`), as the backend tests show.
- **Cause:** FastAPI lists a query model's fields one by one only when the model is the route's only query parameter. In the OpenAPI it also counts the `Pagination` dependency's `limit` and `offset`, so it described `filters` as one object. At runtime it looks at the route alone, so it read the fields flat.
- **Fix:** `CardListQuery(CardFilters)` adds `limit` and `offset` (same bounds as `get_page_params`), and the route takes only that. `test_openapi.py` checks that no query parameter in any route is an object, and that `/api/cards` lists the six params, none required. The API's behaviour didn't change, and the existing card tests pass.
