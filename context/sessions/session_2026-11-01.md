## How it went
1. **Plan** (plan mode): read the plans and the M1 code, and checked two facts:
   - R2 presigned URLs support GET/HEAD/PUT/DELETE only (no POST policy), and they sign `Content-Type`
   - `aiobotocore`'s `generate_presigned_url` is async

   The plan adopted the three proposed decisions and proposed starting params and costs for every module. The user approved it, and asked to commit with the `commit-msg` skill and to merge into `master`.
2. **Git:** checks passed on M1. It was committed as `2f4f231` and merged into `master` (`3dc388f`, `--no-ff`). `m2-content` was branched from there.
3. **Implementation**, step by step:
   - registry and modules
   - catalog
   - shared plumbing
   - models and 4 migrations
   - storage and uploads, written before the card and origin services, so those were written once with art keys
   - services and routers
   - tests
4. **One fix during testing:** `now()` is fixed per transaction, so cards created in one test transaction tied on `created_at`, and "newest first" came out in random order. The content tables now use `clock_timestamp()`. This also matters for M3 imports. The uncommitted migrations were edited in place, the dev DB was re-migrated, and the test DB was dropped so it would be rebuilt.
5. **End-to-end** through nginx against the real stack and R2, then cleanup: the test user and the R2 objects were deleted.

## Decisions made

| Topic | Decision |
|---|---|
| Module costs | Declarative `CostSpec(base, per_param)`. The catalog sends it, so the frontend mirrors the suggestion exactly. |
| Module registry | `ModuleRegistry` class with typed lookups (`registry.get(SpellModule, key)`). Built-ins load lazily on the first lookup. A duplicate key or an incomplete module fails at import. |
| Params schemas | Only types `SchemaForm` can render: bounded ints, numbers, bools, `Literal` enums, arrays of enums. Every schema is inline, with no `$ref`, and has `extra="forbid"`. A test enforces this. |
| Starter params and costs | The table in backend_plan §5 (for example taunt/charge/ranged/lifesteal 2, armor 1 per point, draw_cards 2 per card). These are starting values. |
| System origins | Data migration with literal JSON, found by `system_key`. A check constraint keeps `owner_id` and `system_key` exclusive. A test checks the stored effects against the registry. |
| Origin look | Colour and icon are stored as keys: Okabe–Ito plus grey, and 16 icon keys. The catalog lists them. |
| Errors | Content rules give `AppError` 422 with specific codes (backend_plan §8). Malformed bodies keep FastAPI's 422. `AppError(extra=...)` carries the `origin_in_use` card list. |
| PATCH | Merge, then re-validate the whole object. Null clears optional fields and is rejected for required ones. |
| Pagination | `limit` 1–100 (default 50), `offset`, response `{items, total}`. |
| Card groups | `card_count` is a `column_property`. Delete uses the FK's `ON DELETE SET NULL`. A name collision, including the race, gives 409 `group_name_taken`. |
| Art | Keys are `{card-art\|origin-art}/{user_id}/{uuid}.{ext}`. On save, the prefix is checked and then a `HEAD` (exists, ≤ 2 MiB, allowed type), only when the key changes. The S3 client signs with SigV4. |
| Timestamps | `clock_timestamp()` on content tables (`TimestampMixin`, with `eager_defaults` so async code never lazy-loads them). |
| Tests | A shared `FakeS3` overrides `get_s3`. Each request in a test starts with an empty identity map (`expunge_all`), like a fresh per-request session. |

  - a PUT with the wrong `Content-Type` gives 403 `SignatureDoesNotMatch`
