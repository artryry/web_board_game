## Decisions made

| Topic | Decision |
|---|---|
| Win condition | Every section has HP. An unblocked attacker damages the enemy section in its lane. All enemy sections at 0 HP (or a surrender) ends the game. |
| Rules ("turn flow") | An ordered **phase pipeline** of parameterized modules, stored as JSON. No visual scripting. |
| Lanes | Set in the rules: 1–5, default 3. |
| Board | N creature slots per section, set in the rules (default 3). Creatures move only when a phase allows it. |
| Origins / field types | **Users create origins the same way as cards**, from field-effect modules (at most 3 per origin, each with capped params). System origins (neutral, forest, volcano, ocean, mountain) are seeded as templates. Field type is set **per side**, from each player's deck origin. |
| Card cost | A budget formula **suggests** a mana cost with an under / balanced / over label. **The user always sets the final cost**, and saving is never blocked. |
| Turn timer | Default **90 s**, editable per interactive phase in the rules (10–600 s). |
| Accounts | Registered accounts only (JWT), including for joining a room. |
| Architecture | The **server is authoritative**. A pure, deterministic engine (with a seed and action log, which gives replays). The UI only offers moves from the server's `legal_actions`. |
| Backend stack | FastAPI, SQLAlchemy 2 async with asyncpg, Alembic, Redis (live rooms), MinIO (art, uploaded through presigned URLs), JWT with argon2. |
| Frontend stack | React, TypeScript, Vite, TanStack Query, Zustand, dnd-kit, Framer Motion, Tailwind. Forms are generated from `GET /api/catalog`. |
| Sharing | Importing a shared deck or ruleset **forks** a copy. Rooms copy the ruleset and decks when they're created. |
